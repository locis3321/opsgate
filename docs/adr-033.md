# ADR-033：元工具 `opsgate_invoke`（不依赖客户端刷新工具目录）

- 状态：已实施
- 日期：2026-11-18
- 决策人：用户（在 opencode 实测被阻塞后拍板「改成元工具 opsgate_invoke」）
- 修正：ADR-032 §2.1 的平台工具清单（5 → 7）；ADR-032 §2.5 的「`tools/list` 中不存在调用代理元工具」结论被本 ADR 取代
- 保留：ADR-032 的单入口、`select_scope` 范围语义、品类粒度派生、URL 参数语义、四个暴露层缺陷修复

---

## 1. 背景

ADR-032 把裸 `/mcp` 收敛为平台工具 + `opsgate_select_scope` 动态替换工具集，协议层验证通过：官方 SDK 客户端初始化拿到 5 个工具 → `select_scope` 后收到 `notifications/tools/list_changed` → 重拉得到 15 个含 `host_execute_command`。

但真实客户端 **opencode 2.2.6** 不消费这个通知：

| 观测 | 证据 |
|---|---|
| `select_scope` 返回成功，服务端已替换 `aggregate` | 返回 `{"scope":..., "tools":15}` |
| 客户端本轮的 `tools.*` 命名空间仍是 5 个平台工具 | LLM 报告；调用 `tools.opsgate.mysql_execute_sql` → `Unknown tool` |
| 换轮（`opencode run --continue`）仍不刷新 | 两次独立实测 |
| 服务端协议层完全正常 | SDK 客户端脚本：`{"init":5,"afterSelect":8,"hasMysqlTool":true,"notifications":1}` |

根因：opencode Code Mode 在**同一轮对话开始时构建一次工具目录**，`list_changed` 只更新其 MCP 客户端缓存，不重建运行期命名空间。

结论：**服务端不能把"客户端会刷新工具目录"当作可用性前提。** 必须提供一条在任何客户端都能走的调用路径。

---

## 2. 决策

### 2.1 新增两个平台工具，路径不依赖工具目录刷新

```
opsgate_list_asset_tools  { asset }               → 该资产的工具名 + schema（只读，无密钥）
opsgate_invoke            { asset, tool, args }   → 执行
```

裸 `/mcp` 的平台工具从 5 个变为 **7 个**，仍然与资产数、品类数、分组数完全无关。

标准工作流（写进 `initialize.instructions`）：

```
opsgate_list_assets        找资产
opsgate_list_asset_tools   看这个资产能做什么、参数怎么填
opsgate_invoke             执行
```

### 2.2 `opsgate_invoke` 的 `tool` 必须属于该资产

安全前提是**不新开任意透传口**：handler 用与 `list_asset_tools` **同一份** `toolsOfAsset()` 结果校验 `tool` 名，不在其中 → `-32601`。这样 `tool_filters`（白名单/黑名单）、品类过滤、停用开关、槽位归因全部继续生效，没有一条旁路。

参数形状：

```jsonc
{
  "asset": "host-c",       // id 或 name，取自 opsgate_list_assets
  "tool": "execute_command",         // 取自 opsgate_list_asset_tools（不含品类前缀）
  "args": { "command": "uptime" }    // 该工具自己的参数；不要带 asset
}
```

- `tool` 用**不带品类前缀**的原名，因为前缀是暴露层为消歧造的，资产本身不认识它。
- `args` 非对象 → `-32602`。
- `args.asset` 被框架覆盖为解析后的资产 id（防止模型从两个地方填同一件事）。

### 2.3 `opsgate_list_asset_tools` 返回的 schema 去掉 `asset`

`asset` 已提升为元工具的外层参数。返回的 schema 若仍带 `asset`，会诱导模型在 `args` 里再填一次，且与 `required` 的语义冲突。

### 2.4 `opsgate_select_scope` 保留，降级为「可选优化」

支持 `list_changed` 的客户端仍可用它把整个范围的工具铺开，直接以一等公民工具调用（少一层嵌套，审计里 `tool` 名更直白）。工具描述里已写明这一点，并指向 `opsgate_invoke` 作为不支持时的替代。

**不删除的理由**：它是"工具数与范围解耦"的正解；去掉等于把可预期的未来客户端也锁死在元工具路径上。

### 2.5 对 ADR-032 §2.5 的修正

ADR-032 用一张表论证「不采用 `opsgate_call` 元工具」，结论是「`tools/list` 中不存在调用代理元工具」。

该结论**被推翻**，但不是因为那四条比较错了，而是因为**比较缺少一行**：客户端兼容性。

| | 不采用元工具（ADR-032） | 采用元工具（本 ADR） |
|---|---|---|
| LLM 认知负担 | 低（工具是一等公民） | 需理解"工具里套工具" |
| 上下文 | 恒定为所选范围工具数 | 恒定极小 |
| **客户端兼容性** | **要求消费 `list_changed`** | **任何客户端** |
| 结论 | 作为可选路径保留 | **作为默认路径** |

原表里"不支持 `list_changed` 的客户端会停留在平台工具层"被当作退化路径，实测这个退化路径是**完全不可用**（没有任何资产工具可调），不是退化。

## 3. 实现要点

| 位置 | 变化 |
|---|---|
| `src/services/toolAggregation.ts` | 新增平台工具 `opsgate_list_asset_tools` / `opsgate_invoke`；新增导出 `toolsOfAsset(deps, assetId, principal)`——原生资产按品类取注册表（与解析无关），mcp 资产复用 `derivedToolsOf` + `toolFilters` |
| `src/services/mcpEndpoint.ts` | `callTool` 新增两条路由；新增 `listAssetTools()` / `invokeOnAsset()`；`dispatchDerived` 形参由 `ExposedTool` 收窄为 `toolRef: string`（元工具手里没有 `ExposedTool`，只需真实工具名） |
| `buildInstructions` | `platformOnly` 段改写为元工具三步行；新增第 8 条（`tool` 取值来源、`args` 不带 asset） |

`toolsOfAsset` 是唯一的工具集合真值源：发现（`list_asset_tools`）与执行（`invoke`）共用它，因此**不存在"能列出但不能调"或反之的中间态**。

### 5.2 真实服务复验（8080，重建后重启）

会话：admin key，裸 `/mcp`。

| 步骤 | 结果 |
|---|---|
| `tools/list` | 恰好 7 个，顺序同 §2.1 |
| `initialize.instructions` | 含 `opsgate_invoke`，长度 883 |
| `opsgate_list_assets` | 16 个资产（admin 全量） |
| `list_asset_tools("host-c")` | 4 个原生 host 工具，schema 无 `asset` |
| `invoke("host-a", "host_execute_command", {command:"hostname"})` | `app-node-1`，exit 0 |
| `invoke("host-b", "execute_command", …)` | `cluster-b`，exit 0（派生 MCP 资产） |
| `invoke("mysql-a", "execute_sql", …)` | `ok\n1`（派生 MySQL） |
| `invoke("host-c", "host_execute_command", …)` | `-32002 槽位 "AUTH" 未指定键名…`——**数据问题**（该资产绑定未指定键名），链路本身正常 |
| `invoke("host-b", "host_execute_command")` | `-32601`，提示先 list（该资产是派生 MCP，工具名无 `host_` 前缀）——**防线生效** |
| 上传三步 | request_upload → PUT（197 B）→ upload_status `done` → 主机 `cat` 内容一致 |
| 下载两步 | request_download → GET 内容一致 |

成员（user-b，临时 key，验证后已吊销）：

| 步骤 | 结果 |
|---|---|
| `list_assets` | 12 个（不含 `host-a` 等组外资产） |
| `invoke` 自己可见的 mysql | 成功 |
| `invoke` 组外资产 | `-32006 资产不存在或无权访问`（报文不含资产名） |
| `list_asset_tools` 组外资产 | `-32006`，同上口径 |

### 5.3 opencode LLM 端到端

| 身份 | 提示 | 实际工具序列 | 结论 |
|---|---|---|---|
| admin | 「看 host-a 的主机名」 | list_assets → list_asset_tools → invoke(`execute_command` 失败) → invoke(`host_execute_command` 成功) | 成功；LLM 自行从错误里纠正工具名 |
| user-b | 「查 mysql-a 的数据库版本」 | list_assets → list_asset_tools → invoke(`execute_sql`) | 成功，返回 MySQL 8.4.6 |

这正是 ADR-033 要证明的：**不需要客户端刷新工具目录**，LLM 靠平台工具的返回值自己完成发现与调用。

### 5.4 未覆盖 / 残余风险

- `host-c` 因绑定未指定键名不可用（ADR-031 遗留的 4 条绑定同理），属数据配置项，不在本 ADR 范围。
- `opsgate_invoke` 少一层 schema 强校验：`args` 只校验"是对象"，具体字段由下游工具自身校验（原生走 connector、派生走社区实现）。这是有意的——网关不复制每个工具的 schema 校验逻辑。
- opencode 每次调用前会先 `search(...)`（它自己的代码模式行为），不影响正确性，但多一次往返。
