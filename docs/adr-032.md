# ADR-032：MCP 单入口分层暴露（`opsgate_select_scope`）

- 状态：已实施
- 日期：2026-11-18
- 决策人：用户（提出单入口诉求 + 逐项确认）
- 取代：ADR-021 的「按品类分端点」落地方式（**聚合粒度不变，变的是暴露时机**）
- 部分推翻：J2/J3「无元工具」的**前提**（结论仍成立，见 §2.5）

---

## 1. 背景

### 1.1 症状（实测）

| 入口 | 结果 |
|---|---|
| `POST /mcp`（裸，无参） | **500** `工具数 245 超过上限 200` |
| `/mcp?group=办公室开发服务`（12 资产） | **500** `工具数 233 超过上限 200` |
| `/mcp?category=host` | 200，15 个工具 |
| `/mcp?category=elasticsearch` | **400** `category 仅可选 host/mysql/k8s/other/zabbix/rocketmq/nacos` |

`test/opencode` 里配的正是裸 `/mcp`，因此该客户端**连不上**（`opencode mcp list` → `opsgate_new failed: Request timed out`）。

### 1.2 根因（两条独立）

**根因 A：暴露粒度漂移成「全量平铺」。**
Spec §5.5.1 的目标是「工具数与资产数解耦」，实测这一条是成立的——`?category=host` 下 4 台 host 资产得到 15 个工具，涨到 300 台仍是 15 个（同实现复用同一份 schema，`toolAggregation.ts` 的 `seenByName` 分支；原生工具更是只遍历注册表）。
真正增长的是**品类数**（3 → 11：host/mysql/k8s/other/zabbix/rocketmq/nacos/elasticsearch/mq/monitor/baota/minio）。品类全量叠加 = 245 > 200。

**根因 B：品类白名单与真实数据脱节。**
`TOOL_CATEGORIES` 硬编码 7 个品类，而后来接入的 ES / Kafka / Prometheus / Baota / MinIO 不在其中 →
它们只能靠 `?group=` 连，而所在分组（办公室开发服务）恰恰是最先撞上限的那一个 → 整个品类不可达。

### 1.3 用户的诉求（原话要点）

> 必须保持一个入口；一个入口返回的是 MCP 本身的几个工具，而不是资产的工具入口；
> 模型应该先调用查找资产工具，找到资产，然后根据资产提供的工具完成调用。

并明确补充：**有 300 台虚拟机、100 多个中间件服务**，因此方案必须保证上下文不会随资产数增长。

---

## 2. 决策

### 2.1 `/mcp` 是唯一入口，初始化只给平台工具

初始化（`initialize`）的 `tools/list` 恒定 5 个：

```
opsgate_list_assets    列可见资产（可 search / tag 过滤）
opsgate_view_asset     看资产详情与槽位绑定
opsgate_list_groups    列分组
opsgate_view_group     看分组详情
opsgate_select_scope   选定范围（新增）
```

> **ADR-033 修订**：平台工具实际为 **7 个**，另加 `opsgate_list_asset_tools` + `opsgate_invoke`
> 作为默认调用路径（`select_scope` 降级为可选优化）。origin 见 `docs/adr-033.md`。

不派生任何品类/资产工具。**裸 `/mcp` 的工具数与资产数、品类数、分组数全部无关**，结构上不可能再撞 `tools.list_max`。

### 2.2 `opsgate_select_scope` 的参数是「范围」不是「资产清单」

```jsonc
{ "group": "办公室开发服务", "category": "host", "tag": "prod" }
```

- 三者都可选，至少给一个；全空 → 报错（否则等价于"全部资产"，回到老问题）。
- 调用后：按该范围聚合 → **替换**本会话工具集（不累积）→ `sendToolListChanged()`。
- 返回 `{ scope, assets, tools }`，让 agent 知道当前视图边界。

**为什么是范围而不是资产**：这是 300 台场景的关键。`category=host` 一次覆盖 300 台，工具集仍是同一套 11 个，具体目标是 `asset` 入参。如果按资产逐个 select，300 台就要 select 300 次，且客户端会不停重拉工具列表——不可用。

### 2.3 派生粒度不变：仍是品类

这一点必须写清楚，因为它是"300 台不会爆"的全部依据：

| 事实 | 证据 |
|---|---|
| 同品类同实现 → 复用首份 schema | `toolAggregation.ts` 派生循环的 `existingImpl === impl` 分支 |
| 原生工具只遍历注册表，与资产无关 | 原生循环遍历 `deps.nativeRegistry` |
| 实测 4 台 host = 15 工具 | `?category=host` |

因此 `select_scope({category:"host"})` 后，无论 4 台还是 300 台，工具数都是 11（+4 平台 +1 select）。

### 2.4 URL 参数保留为「初始化视图」

`?group=` / `?category=` / `?tag=` 仍然有效，语义变成"初始化就直接选定该范围"，等价于建会话后立刻调一次 `select_scope`。

- 仍然是同一个入口、同一套范式（不存在"两套行为"）；
- 老客户端与调试脚本不受影响；
- 不带参数 = 停在平台工具层（新默认）。

### 2.5 与 J2/J3 的关系：前提被推翻，结论仍成立

J3 当年否决 `opsgate_list_servers` + `opsgate_call` 元工具，理由是「按品类聚合后工具数已恒定在 30 以内」。

**该前提失效了**（品类 3 → 11）。但解法不是恢复元工具：

| | `opsgate_call` 元工具（被否决） | `opsgate_select_scope`（本 ADR） |
|---|---|---|
| 形态 | 调用代理，参数嵌套 `{asset, tool, args}` | 视图切换，工具仍是一等公民 |
| LLM 认知负担 | 要理解"工具里套工具" | 调用方式不变，只是工具集变了 |
| 上下文 | 恒定极小，但每次调用多一层 | 恒定为所选范围的工具数 |
| 结论 | 不采用 | **采用** |

「`tools/list` 中不存在 `opsgate_call`」这条契约**在 ADR-032 时成立**；但 ADR-033 因 opencode 2.2.6 不消费 `list_changed` 而新增了 `opsgate_invoke` 元工具，该契约随之改写（见 ADR-033 §2.5）。

### 2.6 顺带修掉的四个暴露层缺陷

这些都是"给了 agent 一个用不了的东西"，与本 ADR 同源（都在工具暴露链路上）：

| 编号 | 缺陷 | 修法 |
|---|---|---|
| D1 | `pruneDerivedSchema` 删 `properties` 未删 `required` → `minio_connect_minio` 要求一个不存在的 `port` | 同步过滤 `required` |
| D5 | `writeAuditIntent` 解析 authSlot 失败被 `catch {}` 换成 "Audit unavailable"，真实槽位错误被掩盖 | 凭证解析单独 try/catch，失败记 null；真实错误交给后续 `resolveCredentials` |
| P1 | 原生工具先 push、派生走 `seenByName`，两者不互查 → `host_execute_command` 同视图出现两次 | 两条路径共用同一张查重表 |
| D3 | `?category=` 硬编码白名单 → 5 个品类不可达 | 改为 `servers.category ∪ market_entries.categories` |

### 2.7 `nacos_health`（P2）

**是版本问题**，已确认：`/v1/ns/operator/servers` 在 Nacos 2.x 已移除，实测返回 `501 no such api`；同实例 `/v1/console/server/state` 与 `/v1/console/health/readiness` 均 200。改为调用这两个接口。

### 2.8 instructions：内置骨架不可覆盖，管理员可追加

> **2026-11-18 修订（取代本节原结论）**：用户要求"内置文案可直接优化 + 可在运行参数页修改"，改为**骨架段本身可替换**。
>
> | 项 | 原（ADR-032 初版） | 现 |
> |---|---|---|
> | 设置项语义 | 追加在末尾（「管理员补充说明」段） | 替换骨架段（内置文本成为该项的**默认值**） |
> | 内置骨架 | 代码常量，不可改 | `DEFAULT_WORKFLOW_INSTRUCTIONS`（settingsSchema 导出），改就是改设置 |
> | 动态头部 | 台数/工具数散落在骨架里 | 前移到动态头（`共 N 台；本连接共暴露 M 个工具`），骨架保持纯静态 |
> | 留空 | 只下发内置部分 | 回退内置默认（与从未设置等价） |
> | 预览一致性 | `/mcp/preview` 不含设置与分组说明 | 与 `initialize` 逐字节一致 |
> | UI | 多行编辑 + Markdown 预览 | 同上，另加危险提示条 |
>
> 保留不变的约束：**动态三段（视图名 / 台数 / 工具数 / 分组说明）不可被设置项影响** —— 它们是事实，写死就会变成永久过期信息。
> 新方案的风险从"改不掉骨架"换成"管理员可能删掉安全约束"，用弹窗危险提示 + 「恢复默认」按钮控制，网关不提供第二道兜底。

新增设置项 `mcp.instructions`（`system_settings`，`type=string`，`requiresRestart=false`）：

- **（初版，已作废）** 追加在 `buildInstructions` 末尾，标题「管理员补充说明」；
- **（现行）** 作为骨架段正文；`buildInstructions` 四段结构为 动态头 → 模式段 → 分组说明 → 骨架段；
- 内置工作流是安全约束的默认文本，可由管理员重写（含"一次只处理一个品类"）；
- 前端 Settings 页 `mcp` 分区，弹窗编辑 + Markdown 预览（复用现有 `MarkdownView`，不引入新依赖、不注入 HTML）+ 危险提示条（说明会注入每个 MCP 连接、删除安全约束的后果、留空回退默认）。

"一次只处理一个品类"是本 ADR 的直接产物：视图会随 `select_scope` 变化，必须明确告知模型"处理完一个品类再切"—— 它现在是可编辑的默认文本，不再是不可移除的硬约束。

## 3. 影响

| 项 | 变化 |
|---|---|
| 裸 `/mcp` 工具数 | 245 → **5** |
| `?category=host` 工具数 | 15（不变） |
| `?category=elasticsearch` | 400 → 200（D3 修复后可达） |
| 客户端要求 | 需支持 `notifications/tools/list_changed`。**协议层实测通过**（官方 SDK 客户端：初始化 5 个 → 收到通知 → 重拉得 15 个含 `host_execute_command`）。**opencode 2.2.6 有已知限制**：其 Code Mode 运行时在同一轮对话内构建一次工具目录，轮内不重建——`select_scope` 后本轮的 `tools.*` 命名空间仍是 5 个平台工具。跨轮（下一次 `opencode run`）能拿到新工具集。见 §5.3 |
| 会话状态 | `Session` 新增 `scope` 字段；`aggregate` 由"建会话时固定"变为"可被 `select_scope` 替换" |
| 多 agent | 每会话独立 `randomUUID` + 独立 `aggregate`，一个 select 不影响另一个（有测试锁定） |
| 测试 | `mcp.integration.test.ts` 新增 7 个 ADR-032 用例；2 个既有用例按新契约改写；`settings.test.ts` 不再锁死配置项条数 |
| 不支持 `list_changed` 的客户端 | 会停留在平台工具层。可改用带参 URL（`?category=...`）作为退化路径——仍是同一入口 |

## 4. 验收

| 前置 | 操作 | 预期 | 证据 |
|---|---|---|---|
| admin key | 裸 `/mcp` initialize + tools/list | 恰好 5 个平台工具，不含 `other_echo` | `mcp.integration.test.ts`「裸 /mcp 初始化只给平台工具」 |
| admin key | `select_scope({category:"other"})` 后 tools/list | 含 `other_echo`，平台工具仍在 | 「select_scope 替换工具集」 |
| admin key | 先 select A 再 select B | 工具集为 B，不残留 A | 「替换而非累积」 |
| admin key | `select_scope({})` | `-32602` | 「不带条件 → 报错」 |
| admin key | `select_scope({category:"elasticsearch"})` | `-32602`，报文列出实际品类 | 「不存在的品类」 |
| admin key | 两个会话，一个 select | 另一个不受影响 | 「多会话隔离」 |
| member key | `select_scope({category:"other"})` | assets 只含自己可见的 | 「成员越权不变」 |
| 任意 | tools/list 全工具 | 无 `required` 指向不存在的 `properties` | `tool-exposure-fixes.test.ts`（D1） |
| 任意 | 同视图工具名 | 不重复 | `tool-exposure-fixes.test.ts`（P1） |
| Nacos 2.x 资产 | `nacos_health` | 200，返回 readiness + state | 真实环境实测 |

### 5.3 opencode 限制（本 ADR 的已知缺口）

opencode 2.2.6 Code Mode **在同一轮对话内只构建一次工具目录**，`list_changed` 只更新其 MCP 客户端缓存，不重建 `tools.*` 命名空间；跨轮 `--continue` 同样不刷新。

这不是服务端缺陷（协议层已用 SDK 客户端证明通知正确送达并被消费），但意味着**不能把"客户端会刷新"当作可用性前提**。

→ 已由 **ADR-033** 补上默认路径（`opsgate_list_asset_tools` + `opsgate_invoke`），`select_scope` 降级为可选优化。

### 5.4 未覆盖

- `host-c` / `host-b` / `redis-a` 等 4 条 ADR-031 绑定未指定 `credential_key`，调用报 `-32002`。属数据配置项，需用户在 UI 上补选键名。
