# ADR-029：Market 目录落库 + 后台条目管理

- **状态**：已确认（2026-11-06）
- **取代**：ADR-025 中「Market 目录不落库」「v1 不提供 UI 增删目录条目」「AC-68 无任何 market 表」三项结论
- **保留**：ADR-025 / ADR-003 的「Market 是创建期模板，实例化后与资产彻底解耦」仍然成立且不变

---

## 背景

ADR-025（2026-10-21）把 Market 提级为 v1 必修，但载体定为**内置静态 JSON**（`src/data/market-catalog.json`），并明确「v1 不提供 UI 增删目录条目；需要新增 = 提 PR 改 JSON」，理由是「避免目录变成第二个配置面」。

2026-11-06 用户提出实际使用问题：

> 「我要增加新的 mcp 条目，不是具体的资产，我如何添加？」
> 「后台管理这些分类应该是可以动态添加的」

即：运维人员需要在不改代码、不发版、不重启的前提下增删 MCP 目录条目和分类。静态 JSON 无法满足。

## 决策

Market 目录条目从静态 JSON 迁移至数据库表 `market_entries`，并提供管理员后台管理入口。

### 1. 表结构

```sql
CREATE TABLE market_entries (
  key TEXT PRIMARY KEY,              -- 稳定标识，servers.market_key 引用它
  name TEXT NOT NULL,
  display_name TEXT NOT NULL,
  description TEXT NOT NULL,
  repository TEXT NOT NULL,
  categories TEXT NOT NULL,          -- JSON string[]
  tags TEXT NOT NULL,                -- JSON string[]
  runtime TEXT NOT NULL,             -- 'npm' | 'pypi'
  slot_labels TEXT,                  -- JSON Record<string,string> | null
  installations TEXT NOT NULL,       -- JSON Record<runtime, {command,args,env,url,headers}>
  status TEXT NOT NULL,              -- 'draft' | 'verified' | 'disabled'
  readme_url TEXT,                   -- README 源（PyPI/npm/GitHub）
  readme_cache TEXT,                 -- README 内容缓存
  readme_fetched_at INTEGER,         -- 上次抓取时间戳
  version_pinned TEXT,               -- 锁定版本
  version_latest TEXT,               -- 最新检测版本
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE INDEX market_entries_status_idx ON market_entries(status);
```

字段与现有 `CatalogEntry`（TypeScript）一一对应，**不引入第二套形状**——`detectSlots` / `expandConfig` / `injectSlots` 继续以 `CatalogEntry` 为输入。

### 2. 状态语义

| status | 目录页可见 | 可实例化 | 含义 |
|---|---|---|---|
| `draft` | 管理员可见 | 管理员可 | 新建未验证（新条目默认） |
| `verified` | 所有人可见 | 所有人可 | 已验证可用 |
| `disabled` | 不可见 | 不可 | 停用（已创建的资产不受影响） |

**已创建的资产不受条目状态影响**：实例化时配置已快照固化到 `servers`，`market_key` 仅用于「已添加」徽章与重复检测，运行时不读（ADR-003 / ADR-025 保留结论）。

### 3. 种子导入

现有 13 条 JSON 条目导入为 `status='verified'`（已人工实测通过）。种子幂等：已存在的 `key` 跳过，不覆盖——后台改过的条目不会被 `npm run seed` 冲掉。

### 4. 分类动态聚合

分类从 `market_entries.categories`（JSON 数组）聚合，排除 `disabled`，按条目数降序。前端不再硬编码 mysql/k8s/other。

### 5. 后台管理

仅管理员可增删改条目。删除前检查 `servers.market_key` 引用，有条目引用则拒绝（防止徽章/重复检测失效且不可解释）。

### 6. 保留 JSON 文件

`src/data/market-catalog.json` 保留为**种子数据源**（不是运行时来源），便于离线初始化与回滚。

## 对 AC-68 的修订

原文：`Market 非运行时依赖：数据库 system_settings 为空、market_catalog 无任何表的情况下，已有资产的工具调用全部正常`

修订为：

> **Market 非运行时依赖**：删除或停用任一 `market_entries` 行后，已从该条目创建的资产工具调用行为**完全不变**（配置已快照固化）。Market 表只服务「浏览 + 创建期展开」，不参与 `tools/call` 链路。

原表述中「无任何表」的写法与新决策矛盾，且其**真实意图**（Market 不是运行时实体）在新方案下依然成立，故按意图修订验证条件。

## 影响

| 项 | 影响 |
|---|---|
| `docs/opsgate-spec-v1.md` §5.3 载体行 / 自定义条目行 | 需同步修订 |
| AC-68 | 按上文修订 |
| `src/services/marketCatalog.ts` | `loadCatalog()` 降级为种子源读取；新增 DB 读取层 |
| `src/routes/market.ts` | 目录列表/详情改为查库 |
| 数据库 | 新增 `market_entries` 表 + 迁移 |
| 兼容性 | `servers.market_key` 语义不变，无数据迁移 |

## 未采纳的方案

**A. 继续用静态 JSON + 管理页写文件**：容器内文件系统只读/多副本部署时不可用，且写文件无法与数据库事务一致。

**B. 只加管理页不改存储（前端 localStorage）**：不是服务端共享状态，其他成员看不到，且无法参与实例化校验。

**C. 保留 JSON 为主、DB 仅存覆盖差异**：两套事实来源，违反「不制造多个可写的事实来源」（AGENTS.md §2 第 3 条）。
