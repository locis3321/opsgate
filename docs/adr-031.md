# ADR-031：槽位绑定显式指定凭证键（`credential_key`）

- **状态**：已确认（2026-11-18，用户提出并逐项拍板）
- **补充**：ADR-027（槽位直填值）、ADR-028（一槽多凭证）不变
- **不改动**：`ref.<凭证名>.<键名>` 语法（§5.3）保留，它解决的是另一类场景（见 §2.4）

---

## 1. 背景

### 1.1 触发问题

用户为资产 `tke-host-16.251`（原生 SSH）配置私钥认证，连通性测试报两条错：

1. `Cannot parse privateKey: Encrypted private OpenSSH key detected, but no passphrase given`
2. `连通性测试失败：凭证 cred-xxx 缺少槽位键 "AUTH_PASS"（fail-closed）`

根因是取值靠"猜"：绑定记录只记了"`AUTH_PASS` 用凭证 `cred-xxx`"，至于用凭证里**哪个键**，
由 `pickSlotValue` 按槽位名去推：

```
1. 键名完全一致
2. 归一化后一致（剥品类前缀 + 小写 + 去下划线）
3. 凭证只有 1 个键 → 直接用它
4. 唯一敏感别名（password / privateKey / secret / token / api_key）
```

`AUTH_PASS` 归一化得 `pass`，凭证键是 `passphrase`，四级全不中 → 报错。
用户在最初设计时就提出过：**绑定时应当可以指定"绑定到凭证的某个键"**，本 ADR 落地该能力。

### 1.2 现状盘点（代码事实）

| 位置 | 事实 |
|---|---|
| `src/services/credentials.ts` `pickSlotValue` | 上述四级猜测，槽位名即键名 |
| `frontend/src/components/SlotValueEditor.tsx` `slotMatches` | 前端有一套**平行**的候选过滤规则，与后端猜测规则各自维护、会漂移 |
| `src/config/constants.ts` `REF_RE` | 已有 `ref.<凭证名>.<键名>`，但只能写在资产配置值（`env`/`args`/`headers`）里，**按凭证名**引用，绕过 `server_credentials` 绑定表 —— 用不上 `scope` / `privileges` / 成员自绑 |
| `server_credentials` | 四列主键 `(server_id, slot_name, user_id, credential_id)`，有 `scope` / `label` / `username`，**无"取哪个键"字段** |

### 1.3 影响面实测（用户开发库，20 条绑定）

按"保留同名 + 归一化、去掉后两级猜测"的口径精确统计：

| 结果 | 条数 | 典型 |
|---|---|---|
| 继续可用（同名或归一化命中） | **15** | `RABBITMQ_PASSWORD`←`password`、`MINIO_ACCESS_KEY`←`access_key`、`KUBECONFIG`←`kubeconfig` |
| 将报错（必须显式指定键名） | **5** | `AUTH`←`password`（3 条）、`REDIS_PWD`←`REDIS_PASSWORD`（1 条）、`AUTH_PASS`←`passphrase`（1 条） |

那 5 条正是"槽位名与凭证键名真的不同义"的场景，属本 ADR 的目标场景，不是误伤。

---

## 2. 决策

### 2.1 `server_credentials` 新增 `credential_key`

| 列 | 类型 | 说明 |
|---|---|---|
| `credential_key` | `text` NULL | 该绑定从凭证里取哪个键。**NULL = 按槽位名匹配** |

不变：四列主键、`scope`、`label`、`username`。

> **为什么 `credential_key` 不进主键**：同一槽位绑同一条凭证两次、各取不同键，这种诉求不存在
> （要取两个键就是两个槽位）。进主键会让幂等写入退化成"每次都是新行"。

### 2.2 取值口径改为"精确匹配，不再猜"

`resolveSlotValues` 单个槽位的取值顺序：

```
1. 直填值（ADR-027，不变）
2. credential_key 有值
     → 精确取该键；键不存在 → 抛错（点名槽位、凭证、缺失键、可用键）
3. credential_key 为 NULL
     → 只接受「键名完全一致」或「归一化后一致」
       （剥品类前缀 + 小写 + 去下划线）
     → 都不中 → 抛错，提示「请在绑定上指定键名」
```

**删除**的两级：

- ~~凭证只有 1 个键 → 直接用它~~ —— 这是猜：单键凭证绑多槽位时会把同一个值喂给不同槽位
- ~~唯一敏感别名~~ —— 这是猜：别名表永远追不上下一个产品的命名

**保留**归一化匹配的理由：它是**确定性的字符串等价**（`RABBITMQ_PASSWORD` 与 `password`
在"去品类前缀"规则下是同一个名字），不是启发式。删掉会无谓打断 15 条现存绑定中的 14 条。

### 2.3 槽位是否绑定凭证：仍不做必填校验

本 ADR **不改变**既有口径：槽位没绑凭证就是没绑，写入侧不拦、不强制必填，
由连通性测试 / 产品进程报真实错误。本 ADR 只回答"绑了之后取哪个键"。

### 2.4 与 `ref.<凭证名>.<键名>` 的关系

两者并存，职责不同：

| | `ref.<凭证名>.<键名>` | `credential_key`（本 ADR） |
|---|---|---|
| 写在 | 资产配置值（env/args/headers） | 槽位绑定记录 |
| 指向 | 按**凭证名**全局引用 | 按**绑定**取某条凭证的键 |
| 参与 | 不参与 `scope`/`privileges`/成员自绑 | 完全参与 |
| 适合 | 平台内建条目、管理员统一定义 | 成员给自己的槽位挑键 |

不合并：前者是"配置里写死引用"，后者是"绑定关系上的属性"，合并会让权限模型失真。

### 2.5 接口

`POST /api/v1/servers/:id/slots` 与 `PATCH` 增加可选字段 `credentialKey`：

- 未传 / `null` / 空串 → 存 NULL（按槽位名匹配）
- 传了值 → **写入前校验该凭证确实有这个键**；不存在 → 400，消息列出该凭证的可用键名
- `PATCH` 可单独改 `credentialKey`（用于修复存量绑定）

### 2.6 前端

`SlotBinder` 选中凭证后，同一面板内出现「用哪个键」下拉：

- 数据源：`GET /api/v1/credentials/candidates` 已返回的 `keys` 字段（键名，无值），无需新端点
- 默认选中：与槽位同名或归一化同名的那个键 —— 绝大多数情况用户不用动
- 都不匹配时默认"按槽位名匹配（未指定）"，并把该状态显式标出来
- 选完凭证后若已选键不在该凭证的键里 → 自动清空，不静默保留无效组合

`slotMatches` 的候选过滤**保持不变**（仍允许认证类凭证绑认证槽位）：绑定后由键下拉兜底，
在绑定时就收紧会让"先绑后选键"的流程走不通。

### 2.7 存量数据

按用户决策：**不做自动回填**。那 5 条绑定在改动后首次取值时直接报错，
错误消息明确写出"请在绑定上指定键名"，由用户逐条在界面上重选。

> **已知影响（须明确告知）**：`tke-host-16.251` 的 `AUTH_PASS` 在显式指定键名前**仍然连不上**。
> 2026-11-18 当日为修 `no passphrase given` 做的"口令槽位按 `passphrase` 键取值"改动，
> 属于**猜测链上的特例补丁**；本 ADR 落地后该特例会退回通用口径，
> 必须由用户在绑定上指定 `passphrase` 才生效。

## 3. 影响

| 对象 | 变更 |
|---|---|
| `server_credentials` | 新增 `credential_key text NULL`（迁移 0015） |
| `CredentialService.resolveSlotValues` | 按 §2.2 改写取值；`pickSlotValue` 降为内部"同名/归一化匹配" |
| `CredentialService.resolveSshCredential` | 移除为口令槽位加的特例（退回通用口径） |
| `POST/PATCH /servers/:id/slots` | 接受并校验 `credentialKey` |
| `GET /servers/:id/slots` | 绑定行返回 `credentialKey` |
| 前端 `SlotBinder` | 新增键下拉 |
| `instancePlan` 实例键 | 无需变：它用 `(slotName, credentialId, updatedAt)`，键变更不改值来源身份 |

回滚：迁移只加列，回退只需删列；旧代码读不到该列不受影响。

## 4. 验收

| 项 | 期望 |
|---|---|
| 显式键命中 | `credential_key=passphrase` → 取到口令 |
| 显式键不存在 | 写入 400 并列出可用键；已存数据取值时抛错点名缺失键 |
| 归一化命中 | `RABBITMQ_PASSWORD` ← `password` 继续可用 |
| 单键不再兜底 | 单键凭证 + 异名槽位 → 报错（不再把唯一值当答案） |
| 别名不再兜底 | `AUTH_PASS` ← `passphrase` 不指定键名 → 报错 |
| 无绑定 | 行为不变：不报错、不进注入值（§2.3） |
| 存量 | 15 条同名/归一化绑定用例保持通过；5 条报错消息可定位到具体槽位与凭证 |
| 门禁 | vitest 全量 + 前后端 `tsc --noEmit` + `eslint .` + `check:redlines` |
| 浏览器 | 选凭证后出现键下拉；默认选中同名键；改键后连通性测试通过 |

### 5.3 需要用户执行

那 4 条报错绑定需在资产详情页的凭证绑定区点「改键」指定键名：

| 资产 | 槽位 | 应指定的键 |
|---|---|---|
| `office-host-3.66` | `AUTH` | `password` |
| `office-host-3.58` | `AUTH`（两条绑定） | `password` |
| `office-redis-3.58` | `REDIS_PWD` | `REDIS_PASSWORD` |

在这些绑定改好之前，对应资产的连通性测试与工具调用会报「请在绑定上指定键名」。
