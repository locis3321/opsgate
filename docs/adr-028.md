# ADR-028：凭证共享恢复 + 一槽位多凭证 + 凭证等级

> **状态**：待用户确认
> **日期**：2026-11-06
> **取代**：ADR-020 的"取消共享"结论（§4.2 删除 `visibility`/`shared_with_user_ids` 的决定）
> **关联**：§4.2 credentials、§4.3 server_credentials、§6 权限模型

---

## 1. 背景与动机

### 1.1 Spec 内部矛盾

Spec 存在以下矛盾：
- §0 痛点表、§1 决策 3、§2.3 差异化、ADR-004 都写"**凭证是共享资源**，多人共用同一凭证，审计记到人"
- §6 权限章节保留着旧模型说明：「`reference` 与 `use` 分离的实际意义：把凭证设为 `public` 只意味着"谁都能把它绑到自己资产上"」
- 只有 §4.2 / ADR-020（2026-10-20 标注"最终版"）把 `visibility`、`shared_with_user_ids` 删掉，改成"创建者私有、靠授权资产传播"

ADR-020 是偏离 ADR-004 的孤立改动，实现跟着 ADR-020 走，导致 UI 上没有任何可见等级入口，与用户原始意图（凭证可共享）冲突。

### 1.2 用户确认的新模型（2026-11-06）

用户明确要求：
1. 凭证可共享，但共享的作用域是**分组**
2. 同一资产可绑**多个凭证**（root/开发/只读三个账号）
3. 凭证等级（root/rw/wo/ro）作为展示性元信息，供 LLM agent 选凭证时参考
4. 成员只能绑自己创建的凭证，不能把别人共享的凭证绑到任何资产上
5. 共享不跨组

---

## 2. 决策

### 2.1 凭证归属与管理

| 规则 | 说明 |
|---|---|
| 归属 | 凭证是创建者私有资源，仅 owner + admin 可改值/轮换/删除 |
| 等级 | 新增 `privileges` 字段（枚举：root/rw/wo/ro，可多选），仅展示性元信息，不参与授权判定 |
| 共享开关 | 凭证 owner 可在凭证详情页，按分组逐个开关"该凭证是否对某分组共享" |
| 不跨组 | A1 在 G 组共享 ≠ 在 F 组共享 |

### 2.2 绑定规则

| 规则 | 说明 |
|---|---|
| 候选列表 | 资产绑定凭证时，候选列表 = **只有自己创建的凭证**（共享的凭证只能"用"，不能"绑"） |
| 多绑定 | 同一资产同一槽位可有多条绑定记录（通过"添加绑定"按钮） |
| 修改权限 | 每条绑定记录只能被**添加者本人**修改/删除 |
| 示例 | A 创建 A1，绑到资产 C，在 G 组共享 C 和 A1。G 组成员 B 可以使用 C（用 A1），但 B 不能把 A1 绑到任何资产上 |

### 2.3 数据模型变更

#### credentials 表新增字段

```sql
ALTER TABLE credentials ADD COLUMN privileges TEXT NOT NULL DEFAULT '[]';
-- JSON: ["root","rw"] 仅展示
```

#### 新表 credential_group_shares

```sql
CREATE TABLE credential_group_shares (
  credential_id TEXT NOT NULL REFERENCES credentials(id) ON DELETE CASCADE,
  group_id TEXT NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
  created_at INTEGER NOT NULL DEFAULT (strftime('%s', 'now') * 1000),
  PRIMARY KEY (credential_id, group_id)
);
```

#### server_credentials 主键改造

```sql
-- 旧主键
(server_id, slot_name)

-- 新主键
(server_id, slot_name, user_id)

-- 新增字段
scope: 'asset' | 'personal'
  asset    = owner 绑定，全组使用者共享
  personal = 成员自己绑定，仅本人可见可用
label: TEXT  -- 同一槽位多凭证的区分名，如 "root 账号"
```

**迁移策略**：
1. 现有数据全部标记为 `user_id = owner_id`、`scope = 'asset'`、`label = NULL`
2. 新绑定写入时带 `user_id` 和 `scope`

### 2.4 调用取值与可见性

#### tools/call 新增 credential 参数

```typescript
// 可选参数
credential?: string  // credentialId

// 取值顺序（未传 credential 时）
1. 调用者自己绑定的凭证（personal）
2. owner 绑定的凭证（asset），按 privileges 排序：admin/root → rw → wo → ro → 无等级
3. 都没有 → fail-closed
```

#### LLM agent 可见性

- owner 没共享的凭证，其他成员从 agent 视角**看不到**
- 成员只能看到自己绑定的凭证 + owner 已共享的凭证（但只能"用"不能"绑"）

### 2.5 成员变动

| 场景 | 处理 |
|---|---|
| 成员从分组移除 | personal 绑定保留（因为是他自己绑的）；不能再使用 owner 绑定的凭证（资产不可见 → 使用权派生失败） |
| 成员从平台删除 | 凭证和资产都保留；`owner_id` 置空（`NULL`）；平台 admin 可重新分配 owner 或直接管理 |
| 成员被禁用 | 只禁止平台登录（Web UI）；**不禁止** LLM 的 MCP 调用（agent 仍可调用该成员绑定的凭证） |

### 2.6 副作用

凭证轮换 → `updated_at` 变化 → 所有绑定该凭证的资产实例失效重建：
- owner 绑定（asset scope）→ 影响全组使用者
- personal 绑定 → 只影响本人

## 4. 验收标准

| # | 验收项 | 证据 |
|---|---|---|
| AC-1 | 凭证可设置 privileges（root/rw/wo/ro），仅展示不参与授权 | 创建凭证时选择，列表/详情显示徽标 |
| AC-2 | 凭证 owner 可按分组逐个开关共享 | 凭证详情页"共享至分组"面板，开关写 credential_group_shares |
| AC-3 | 共享不跨组 | A1 在 G 组共享，F 组成员不可见 |
| AC-4 | 资产绑定凭证候选列表 = 只有自己创建的凭证 | 下拉列表不含他人凭证 |
| AC-5 | 同一资产同一槽位可有多条绑定记录 | 添加绑定按钮，列表显示多行 |
| AC-6 | 每条绑定记录只能被添加者本人修改/删除 | 非添加者看不到修改/删除按钮 |
| AC-7 | 成员可使用 owner 共享的凭证，但不能绑到任何资产 | B 可用 A1 调用 C，但不能把 A1 绑到 D |
| AC-8 | tools/call 支持 credential 参数 | 传指定 credentialId 用该凭证 |
| AC-9 | 未传 credential 时按 personal → asset 顺序取值 | 优先取自己绑的，再取 owner 绑的 |
| AC-10 | owner 没共享的凭证，其他成员从 agent 视角看不到 | 工具描述中不列出未共享凭证 |
| AC-11 | 成员从分组移除后 personal 绑定保留 | 绑定记录仍在，但不可用 owner 凭证 |
| AC-12 | 成员删除后凭证/资产保留，owner_id 置空 | 记录仍在，admin 可重新分配 |
| AC-13 | 成员禁用只禁登录，不禁 MCP 调用 | 禁用后 agent 仍可调用 |
| AC-14 | 凭证轮换影响范围正确 | asset scope 影响全组，personal 只影响本人 |

## 5. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 取代 ADR-020 的"取消共享"结论 | Spec 内部矛盾，用户原始意图是凭证可共享 |
| D2 | 共享作用域是分组，不是资产 | 用户明确要求，与资产可见性解耦 |
| D3 | 成员只能绑自己创建的凭证 | 防止"借他人凭证绑自己资产"的转授权路径 |
| D4 | server_credentials 主键加 user_id | 支持一槽位多凭证，区分 owner/成员绑定 |
| D5 | 调用取值顺序 personal → asset | 成员优先用自己的，再用 owner 共享的 |
| D6 | 成员删除后 owner_id 置空而非级联删除 | 审计需要保留记录，admin 可重新分配 |
| D7 | 成员禁用不禁 MCP 调用 | 禁用只禁 Web UI，agent 调用是独立通道 |
